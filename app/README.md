# 서울메이트 앱 공통 기반

Expo와 TypeScript 기반의 앱입니다. 공통 UI와 이메일 인증, 회원 등록 및 조회, 온보딩, 여행 일정과 지도 탐색을 포함합니다. 앱 A의 선택 지도와 스팟 상세, 채팅, 여행 완료, 마이와 신고 및 차단 화면의 로컬 연결도 포함합니다. 소셜 로그인은 준비 중입니다. 이 문서는 로컬 후보의 코드 범위를 설명하며 실제 서비스와 Native 기기 검증 완료를 뜻하지 않습니다. Refs #8, #22.

## 시작

Node.js 24에서 저장소 루트의 `app`으로 이동해 실행합니다.

```bash
npm ci
npx expo start
```

웹은 `npx expo start --web`, 타입 검사는 `npm run typecheck`, 패키지 호환 검사는 `npx expo install --check`입니다. 오프라인 호환 검사는 Expo의 로컬 버전 목록을 사용하므로 온라인 확인과 구분해야 합니다.

앱 B는 `src/theme.ts`의 `theme`과 `src/ui.tsx`의 공통 컴포넌트를 import할 수 있습니다. `src/state.tsx`는 선택한 역할과 언어에 따른 표시 기반을 제공합니다. 예를 들어 앱의 `app` 폴더에 있는 화면에서는 다음과 같이 사용합니다.

```tsx
import { View } from "react-native";
import { theme } from "../src/theme";
import { Label } from "../src/ui";

export function NoticeBox() {
  return (
    <View style={{ padding: theme.space.lg }}>
      <Label>준비 중입니다</Label>
    </View>
  );
}
```

공통 `Label`은 선택한 역할에 맞춰 폰트를 적용합니다. `theme.typography`에는 폰트 패밀리가 포함되지 않으므로 React Native `Text`에 해당 스타일만 적용해도 폰트가 자동 선택되지는 않습니다.

## 디자인 기준과 현재 구현

현재 전달된 디자인 기준은 개발 전달 패키지 v5의 `DESIGN.md` v4.0과 토큰 v3입니다. 저장소 루트 README의 개발 전달 패키지 v4 설명은 이전 시점의 기준입니다. 화면별 기능과 상태는 최신 화면 명세를 함께 확인합니다. 최신 기준이 전달됐다고 해서 모든 화면이 이를 반영했거나 실기기에서 검증됐다는 뜻은 아닙니다.

- **색상과 호환:** `src/theme.ts`는 `brand` `#477EFF`, `brandDeep` `#2F6BF0`, `brandTint` `#F0F5FF`, `accent` `#FFD84D`와 회색 및 의미 색상을 정의합니다. 앱 B 호환을 위한 기존 색상 별칭도 유지합니다.
- **폰트:** 본문은 역할별 `Noto Sans KR`과 `Noto Sans JP`의 400, 500, 600, 700을 사용합니다. 워드마크는 `Cafe24 Ssurround`와 `Zen Maru Gothic 900`을 사용합니다. 기존 글꼴 파일은 호환을 위해 보존합니다.
- **공통 UI:** `src/ui.tsx`에 `Screen`, `Label`, `Button`, `Card`, `Input`, `Chip`, `BottomSheet`, `AppBar`, `Notice`, `ProgressTracker`, `TextLink`가 있습니다. 토큰상 주요 버튼은 높이 56과 반경 16, 짝 버튼은 48과 14, 작은 버튼은 44와 12이며 입력은 높이 55와 반경 14, 시트는 반경 28입니다. 화면별 적용과 실제 기기 동작은 별도로 확인해야 합니다.
- **배포 설정:** `app.json`에는 앱 식별과 EAS 프로젝트 설정이 있고 `eas.json`에는 development, preview, production 프로필이 있습니다. preview와 production의 배포 검증 스크립트는 공개 API 및 인증 설정의 형식을 검사합니다. 형식 검사는 연결 성공이나 배포 완료를 보장하지 않습니다.

### 이전 회의와 최신 전달의 차이

- 이전 문서는 스플래시 슬로건과 B안 로고를 기준으로 설명했습니다. 현재 `app/index.tsx`와 로그인 화면의 표시 문구 및 로고가 최신 디자인 v4.0의 슬로건과 H1 기준에 모두 맞는지는 별도 대조가 필요합니다.
- 이전 회의에서는 로그인 상단에 한강과 롯데타워 사진을 쓰기로 했습니다. 최신 전달은 서울 일러스트를 사용하며, 현재 `app/auth.tsx`는 SVG 자리 표시자를 사용합니다. 전달된 로그인 일러스트는 아직 연결되지 않았습니다.
- 최신 전달은 별점과 상호 후기 UI를 제외합니다. 스팟 API의 `review` 필드는 메이트가 작성한 스팟 소개이며 별점이나 상호 후기와 다릅니다. 별도의 상호 후기 서버 API는 기존 코드에 남아 있습니다.
- 이전 회의에서는 상단 검색으로 장소를 추가하고 공개 중인 지도는 수정할 수 없도록 안내했습니다. 최신 전달은 공개 중 수정과 매칭 시점의 지도 고정을 요구합니다. 현재 서버는 여행 중 지도 이름과 기존 스팟 변경, 공개 스팟 지정을 제한하고 공개 스팟의 수정과 삭제도 제한합니다. 현재 코스 조회는 매칭된 지도 ID로 현재 스팟을 읽습니다. 최신 스냅샷 정책과 차이가 있어 서버와 협의가 필요합니다.
- 이전 회의에서 회원가입 여정과 오류 흐름, 앱 아이콘 및 지도 검색바의 추가 전달이 남아 있었습니다. 현재 아이콘 설정과 관련 화면 코드가 있으나 최신 화면과 실기기 결과는 별도 확인이 필요합니다.

`.env.example`은 공개 설정의 이름과 형식 예시입니다. `EXPO_PUBLIC_` 값은 앱에 포함되므로 공개 가능한 값만 사용하고 비밀 키, DB 비밀번호와 LLM 키를 넣지 않습니다. 예시의 네이버 지도 항목은 현재 후보에 SDK나 플러그인이 포함됐다는 뜻이 아닙니다.

## 온보딩 1차 구현 (본인 인증 시연 및 프로필 등록)

여행자(`T-03`, `T-04`)와 메이트(`M-02`, `M-03`)가 공용으로 사용하는 본인 인증 시연 화면과 프로필 등록 화면을 `app/(onboarding)/` 및 `src/features/onboarding/`에 유지했습니다.

- 본인 인증 시연(`USER-02`)은 웹에서 `Blob`, 네이티브에서 `expo-file-system` 임시 캐시 파일 URI 또는 `expo-image-picker` 선택 URI를 `passportImage` multipart로 전송하고 완료 후 `USER-01`로 상태를 재확인하며 임시 파일과 여권 이미지는 보관하지 않습니다.
- 프로필 등록(`USER-03`)은 UTF-16 기준 닉네임 2~8자 및 소개 200자 카운터와 입력 검증을 일치시켰고, 성별, 출생연도 만 18세 검증, 선택 프로필 사진 업로드(15초 제한 및 취소 제어 포함)를 지원하며 저장 후 `USER-01`을 다시 확인합니다.
- 최신 화면 명세의 성별 `응답 안 함` 선택지는 현재 서버 `Gender` enum(`MALE`, `FEMALE`)에서 미지원 상태이므로 임의 성별로 변환하지 않고 안내 후 저장을 차단합니다.
- 실제 `images` 버킷 업로드 정책, 배포된 Spring API 주소와 웹 CORS, 실제 기기의 네이티브 폰트 로드와 카메라 및 사진 권한 동작은 아직 검증하지 않았습니다.

## 취향 온보딩

- 여행자와 메이트는 서버에서 취향 목록을 조회하고 일반 취향, 세부 항목, 최애와 동네를 선택합니다. 일반 취향을 하나 이상 선택해야 저장할 수 있습니다.
- 선택은 계정별 메모리 초안으로 유지하며 목록의 ID 또는 의미가 바뀌면 재선택을 안내합니다. 저장 후 회원 정보를 다시 조회하고 선택 ID를 대조합니다.
- 메이트의 최초 저장은 첫 지도 만들기로 연결하며, 이미 저장한 취향을 수정하면 계정 화면으로 돌아갑니다. 여행자의 매칭 조건은 임시 연령대 복수 선택으로 저장합니다. 최신 디자인의 18세부터 50세 이상까지 직접 고르는 범위 조절은 적용되지 않았으며 서버 계약 조율이 필요합니다.
- 격리 모의 환경에서 동작을 확인했으며 실제 서버와 실기기 동작은 확인하지 않았습니다.

## 여행 일정과 지도 탐색

여행자의 일정 화면은 조건 완료 뒤 진입하며 서버 저장 확인과 회원 상태 재조회 후 이동합니다. 매칭 조건의 나이 범위 UI는 서버 계약 확인이 필요합니다. 일정만 다시 필요한 계정은 탭과 완료 기록에 접근할 수 있으며 새 지도 탐색은 일정 가드를 거칩니다.

지도 탐색 목록과 공개 미리보기는 서버 응답에 연결돼 있습니다. 현재 서버의 목록 카드 응답에는 스팟 사진과 공통 취향 수가 없으므로 최신 디자인의 해당 정보를 제품 데이터로 표시할 수 없습니다. 서버는 공통 취향 수를 정렬 계산에 사용하지만 목록 응답에는 포함하지 않습니다. 시연용 샘플은 실제 서버 데이터가 아닙니다.

## 앱 A 내부 연결과 남은 검증

- 선택한 지도와 스팟 상세는 매칭별 코스 정보를 조회하고 앱 B의 방문 인증 및 방문 기록 경로로 연결합니다. 지도 SDK 영역은 주입 경계만 준비되어 있고 실제 지도 렌더러는 연결되지 않았습니다. 지도 SDK와 메이트 지도 편집, 방문 인증과 앨범 화면은 앱 B 담당 범위입니다.
- 여행 완료는 서버 상태와 앨범 확인을 거쳐 연결합니다. 완료 요청의 결과가 불확실하면 계정과 매칭별 메모리에서 중복 요청을 막고 재조회로 확인합니다. 이 보호는 앱 프로세스가 유지되는 동안의 메모리에 한정되며 재시작 후에도 유지되는 보장은 없습니다.
- 마이는 회원 정보와 서버 통계를 표시하고, 신고 및 차단은 별도 확인과 요청 상태 처리를 사용합니다. 알림은 유형과 역할에 맞는 경로로 이동하며 채팅은 계정 및 매칭별 접근 상태를 확인합니다. 완료된 매칭의 열린 채팅은 기록을 읽을 수 있고 새 채팅 열기와 전송은 막습니다. 실제 서비스와 폰에서 각 흐름을 검증해야 합니다.

## 데이터 로딩 표시

`src/loading.tsx`의 `LoadingSkeleton`은 최초 데이터 조회 시 실제 콘텐츠 위치에 사용합니다. `shape`로 카드, 칩, 폼, 달력, 프로필, 알림 행, 지도 상세 형태를 고르고 화면 언어에 맞는 `label`을 전달합니다. 모션 줄이기 설정에서는 정적으로 표시합니다. 재조회에서는 기존 결과가 안전하게 남을 수 있는지 판단하고 갱신 상태를 알립니다. 더 보기는 목록 하단에서 표시하며 저장과 같은 변경 작업은 기존 버튼 로딩 표시를 사용합니다.
