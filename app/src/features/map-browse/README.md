# 지도 찾기와 매칭

`createMapBrowseApi(request?)`는 인증 토큰을 명시적으로 받는 조회 어댑터다. `browse(token, filters, page, signal?)`와 `preview(token, mapId, signal?)`는 검증된 DTO를 반환하고 요청 오류를 그대로 전파한다. 기본 요청은 공통 `apiRequest`이며 주입 요청은 동일한 인자를 받는다. 응답은 허용된 필드만 복사한다. 숨긴 스팟은 개수만 사용한다.

필터의 `sort` 생략은 추천순이다. `minPins`는 5 이상, `maxPins` 생략은 상한 없음, `size`는 1부터 50, `areaTagId`는 서버 태그의 AREA ID다. 숫자 형식은 로컬에서 검증하고 해당 ID가 AREA인지 서버가 검증한다. 페이지는 0부터 시작한다. `minPins`, `maxPins`, `page`의 최대 2147483647은 서버 Integer 전송 타입 제약이며 제품 선택 상한이 아니다.

`createBrowseController(api)`는 화면 또는 계정 수명마다 생성한다. `setAccount(accountId, token)` 이후 `setFilters(filters)` 또는 `refresh()`로 첫 페이지를 읽고 `nextPage()`로 이어 읽는다. `getState()`는 복사본을 반환한다. 오류는 상태의 `error`에 보존되며 다음 페이지 실패 시 기존 결과를 유지한다. 필터와 계정 변경은 기존 요청을 취소하고 늦은 응답을 무시한다. 같은 계정과 같은 토큰을 다시 전달하면 상태와 진행 요청을 유지한다. 같은 계정의 토큰이 바뀌면 이전 토큰 요청을 취소하고 기존 필터와 결과를 유지하며 자동으로 재조회하지 않는다. 취소된 조회를 다시 실행하려면 `refresh()` 또는 필요한 경우 `nextPage()`를 호출한다. 다른 계정으로 변경하거나 로그아웃하면 필터와 결과를 즉시 폐기한다. `cancel()`은 진행 요청을 무효화하며 `dispose()` 후 새 인스턴스가 필요하다. 화면은 호출 직후와 Promise 종료 후 상태를 읽어 렌더링해야 한다. 중복 mapId는 먼저 받은 카드를 유지하고 서버의 totalCount, hasNext, emptyReason은 마지막 페이지 응답을 그대로 유지한다.

여행자는 `/explore`에서 지도 목록과 지역 및 핀 범위 필터를 사용하고 `/explore/[mapId]`에서 공개 스팟을 확인한다. 홈은 활성 매칭과 서버 슬롯을 표시한다. 목록 필터와 취소 확인에는 공용 `BottomSheet`를 사용한다.

`createMatchApi(request?)`는 인증 토큰을 명시적으로 받아 활성 매칭과 슬롯 조회, 지도 선택 및 취소를 요청한다. `createMatchFlow(api)`는 쓰기 전후의 미리보기와 활성 목록을 대조한다. 활성 매칭의 `courseMap`이 null이면 슬롯에는 포함하되 미리보기로 이동하지 않는다. 선택 성공 응답은 매칭 ID, 지도 ID, 상태와 슬롯을 검증하고 후속 조회의 매칭 ID와 일치해야 요청 성공으로 확정한다. 취소 성공 응답은 대상 매칭 ID와 상태를 검증한다. 네트워크 오류나 중복 선택 등으로 결과가 불확실할 때는 자동으로 재전송하지 않고 서버 상태를 재조회한다. 재조회로 확인한 현재 상태와 해당 요청의 성공 확인은 구분한다. 화면 이탈과 계정 변경은 요청의 신호와 수명 가드로 처리하며 전송된 쓰기의 롤백을 보장하지 않는다.

공개 좌표 위치도에는 지도 배경이 없다. 실제 Native 지도와 실제 서버 저장 및 휴대폰 동작은 검증하지 않았다.
