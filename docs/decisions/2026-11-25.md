### 11/25 결정 사항 (회의록 추가용)

**유료화**
- 유료화는 MVP에서 제외. 발표에서 확장성(칸 추가, 프리미엄 지도, 제휴)으로만 언급
- 여행자 매칭 칸은 **무료 5칸** (기존: 무료 1칸 + 결제 시 추가)
  - 칸 1개 = 메이트 1명 = 코스 지도 1개. 동시에 서로 다른 메이트 5명까지 매칭 가능
  - 이유: 2박 3일 중 1일차는 카페, 2일차는 관광지처럼 날마다 다른 코스로 여행할 수 있고, 한국인 친구도 더 많이 사귈 수 있음
- 유료 칸 추가 화면(F-UI-19)은 삭제

**신고·차단**
- 신고·차단 모두 여행자·메이트 양쪽 가능, **매칭 후 언제든** (기존: 차단은 채팅이 열린 뒤에만)
- 차단 시 사유 선택 필수. 진행 중 매칭은 종료되고 칸 반환
- 차단당한 쪽에는 "매칭이 종료되었습니다"라고만 알림 (차단 사실은 밝히지 않음)
- 정당한 이유 없는 일방적 차단·신고 대응
  - MVP: 차단 사유와 차단당한 쪽의 피드백(1회)을 저장까지만
  - 확장(발표): 소통 기록·피드백을 AI나 관리자가 보고 판단해 불이익(목록 노출 제한 등)

**역할 분담 (개발 4명)**
- 서버 A (장진용): 골격(JWT·공통 에러·마이그레이션·CI), 온보딩 API, 알림, 매칭(신청·취소·칸·정원·상태), 지도 목록·코스 선택, 채팅, 자동 종료·완료, 신고·차단
- 서버 B (정선우): 시드 데이터, 지도·스팟 API, 메이트 찾기, 방문 인증(200m·시연 모드), 방문 기록·리액션, 번역, 앨범·후기
- 앱 A (류우진): 앱 뼈대(Expo·라우팅·다국어·로그인), 온보딩, 메이트 찾기·여행자 홈, 지도 목록·코스 선택, 채팅, 코스 지도, 여행 완료, 마이페이지
- 앱 B (최병찬): 지도 SDK, 메이트 홈·지도 생성·스팟 등록, 방문 인증 화면, 방문 기록·리액션, 알림 목록, 번역 표시, 앨범·후기

**미정**
- 취향 카테고리 종류와 개수 (초안: 카페·맛집 / 산책·동네 / 문화 / 쇼핑 / 동네, 세부 23개)
